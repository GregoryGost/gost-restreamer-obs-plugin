# GOST Restreamer — плагин OBS

Нативный плагин OBS Studio для управления отдельным сервером
[GOST Restreamer](https://github.com/GregoryGost/gost-restreamer): компактный Dock
и одно расширенное окно управления и настроек. OBS создаёт один штатный
медиапоток; плагин предоставляет интерфейс, REST/SSE-клиент и согласует команды.

Требования, границы компонентов и критерии приёмки описаны в
[архитектуре проекта](gost-obs-plugin-architecture.md). Целевой стек: Windows
10/11 x64, OBS Studio 33.0.1, C++20, Qt 6 Core/Widgets/Network, MSVC и CMake.
Репозиторий находится на этапе подготовки: исходники плагина, CMake, тесты и
установщик пока не созданы.

## Работа с Codex

Подключён выбранный набор
[agent-projects-tools](https://github.com/GregoryGost/agent-projects-tools/tree/ff4393f50c7d2e47cc03197e6e45ed087c89c954).
Сначала агент читает [AGENTS.md](AGENTS.md), затем обязательную
[маршрутизацию](.codex/rules/request_routing.md) и
[профиль проекта](CODEX_PROJECT.md). Профиль задаёт точные активные материалы,
границы делегирования, язык, доступность инструментов и правила приёмки.

| Область | Подключённые материалы |
| --- | --- |
| Маршрутизация и общие правила | Request routing, проверка зависимостей, координация субагентов, source code hygiene, Git |
| Техническая документация | Context7 с проверкой применимой версии и переходом к официальным источникам при необходимости |
| Язык пояснений рядом с кодом | `comment-language-audit`; комментарии, описания тестов, Git и собственная документация — на русском |
| C++ | Core, стиль, CMake, тестирование; стандарт проекта C++20 |
| Qt 6 | Core, Widgets, Testing и Quick/QML |

QML активирован для будущих задач по выбору владельца. Текущий интерфейс
проектируется на Widgets; подключение материалов не добавляет QML runtime,
исходники или новые окна. Версии Qt/OBS SDK и реальные команды сборки будут
закреплены при создании каркаса; текущую инвентаризацию см. в профиле.

В [.codex/agents/](.codex/agents/) находятся девять специализированных ролей:
два независимых архитектора, исследователи кода и документации, исполнители
простых и сложных изменений, тестировщик, специалист по ревью и диагност сложных ошибок.
Модели и effort перечислены в профиле. Выбранные роли используются только для
разрешённой работы с исполняемым кодом/тестами; инструкции и документацию
обрабатывает основной агент. Для архитектурных задач действует согласование
единой редакции обоими архитекторами; тесты и ревью проверяют стабильный снимок.
Архитектор БД не подключён: SQLite и миграции принадлежат отдельному backend.

### Локальная конфигурация

`.codex/config.toml` игнорируется Git и хранит локальные настройки, включая
аутентификацию MCP. Пример без секретов:
[.codex/config.example.toml](.codex/config.example.toml). Если локального файла
ещё нет, его можно создать из примера в PowerShell:

```powershell
if (-not (Test-Path -LiteralPath .codex/config.toml)) {
    Copy-Item -LiteralPath .codex/config.example.toml -Destination .codex/config.toml
}
```

Если файл существует, объедините нужные параметры, сохранив свои настройки.
В доверенном проекте актуальный Codex обнаруживает отдельные TOML-файлы ролей
из `.codex/agents/`; формат описан в
[официальной документации субагентов](https://learn.chatgpt.com/docs/agent-configuration/subagents).
Загрузка project config зависит от доверия к проекту и ограничений клиента;
доступность моделей/effort проверяется в конкретном аккаунте. Пример не меняет
модель уже работающей сессии.

Полные пакеты навыков с references находятся в [.agents/skills/](.agents/skills/).
Их наличие не заменяет активацию и проверку hard dependencies из профиля.
SDK, расширения редактора и дополнительные MCP этой интеграцией не устанавливаются.

### Обновление набора

Обновление выполняется явно: сопоставьте изменения upstream,
сохраните проектные дополнения `AGENTS.md`,
согласованно обновите bootstrap, rules, выбранные роли и полные пакеты навыков,
затем перепроверьте профиль, зависимости, ссылки и TOML. Не активируйте новые
материалы только из-за их появления в upstream.
