# GOST Restreamer — плагин OBS

Нативный плагин OBS Studio для подключения к серверу
[GOST Restreamer](https://github.com/GregoryGost/gost-restreamer).
Компактный Dock показывает состояние подключения и выбранный поток,
а отдельное окно содержит управление и настройки.

Проект находится в разработке. Сейчас доступны подключение к серверу,
автоподключение и восстановление связи, выбор потока и сохранение настроек.
Выбор запоминается отдельно для каждого сервера и профиля OBS;
переименование профиля сохраняет его привязки. Интерфейс доступен на русском
и английском языках.

Управление эфиром и отдельными выходами выполняется через существующий API
сервера. Dock показывает локальную статистику OBS и серверные наблюдения отдельно.
Окно управления позволяет редактировать потоки, назначения, группы и профили.
Загрузка заглушек и полная диагностика пока не завершены.
Кодирование и отправка исходного медиапотока выполняются штатными
средствами OBS; для управления нужен заранее настроенный сервер.

## Совместимость

- Windows 10/11 x64.
- OBS Studio 33.0.1.
- Отдельный сервер GOST Restreamer с HTTP/HTTPS API контракта dev.8 (`252669d05440`).

Поддержка Linux и macOS пока не заявляется. Контракт серверного API
и границы совместимости описаны в [архитектуре проекта](gost-obs-plugin-architecture.md).

## Установка

Установщик пока не подготовлен. Плагин можно [собрать из исходников](#сборка).
После сборки и установки в staging каталог плагина имеет следующую структуру:

```text
build/install/gost-restreamer-obs-plugin/
  gost-restreamer-obs-plugin.dll
  gost-restreamer-obs-plugin.pdb    (символы отладки, если доступны)
  data/locale/ru-RU.ini
  data/locale/en-US.ini
```

Закройте OBS и скопируйте каталог `gost-restreamer-obs-plugin` целиком:

- для обычной установки OBS — в `%ProgramData%/obs-studio/plugins/`;
- для portable OBS — в `<OBS>/plugins/`.

Затем запустите OBS. DLL должна находиться непосредственно в каталоге плагина,
рядом с `data/`.

## Подключение

1. В меню OBS «Сервис» выберите «GOST Restreamer» и откройте раздел «Настройки».
2. Укажите корневой адрес API, например `http://192.168.1.100:8080`, без `/api/v1`.
3. Нажмите «Сохранить» и дождитесь загрузки списка потоков. «Отмена» сбрасывает введённый адрес.
4. Выберите нужный Stream в шапке Dock.

Статус подключения справа от выбора потока отображается прописными буквами.
Повторный выбор «Сервис → GOST Restreamer» активирует прежнее окно управления.

«Сохранить» подтверждает применение адреса. При следующем запуске OBS подключение
и восстановление временных сбоев выполняются автоматически, без переключателей.
После завершённого отказа тот же адрес можно повторно применить кнопкой «Сохранить».
Подключение само по себе не запускает эфир. RTMP Server и Stream Key вводятся
в штатных настройках трансляции OBS.

При возвращении к серверу или профилю OBS восстанавливается сохранённый
для этой пары поток. Новые и дублированные профили получают собственные привязки.
Переименование через OBS сохраняет выбор, в том числе после перезапуска.
Ручное перемещение каталогов профилей при выключенном плагине автоматически
не распознаётся как переименование.

Настройки сохраняются в `settings.json` каталога конфигурации плагина;
в portable OBS он находится внутри `config/`. Серверные ключи, адреса
назначений и метрики в этот файл не записываются. Ошибка сохранения показывается
в интерфейсе; повреждённый или неизвестный формат файла не перезаписывается.

Язык и оформление следуют OBS. В разделе «Расширенные» задаются общий срок
обычного REST-запроса (5–60 секунд, по умолчанию 15) и режим клиентского журнала
«Обычный»/«Подробный», а также лимит повторов отклонённой подписки SSE.
Изменения применяются вместе по кнопке «Сохранить»; «Отмена» возвращает
действующие значения без записи. До сохранения ввод остаётся в форме,
в том числе при переходе в другой раздел и повторном открытии окна.
Срок применяется к новым запросам; SSE и командные
операции имеют отдельные бюджеты. Записи направляются в штатный журнал OBS.
Отказ явного действия показывается в одном всплывающем окне: причина и известный
следующий шаг отображаются отдельно. Уже открытое окно переиспользуется.
Каждый отказ записывается в журнал с полученной диагностикой, включая
присутствующие секретные значения. В Dock и настройках причина отказа
не дублируется. Обычные технические записи не выгружают успешные ответы,
тела всех запросов или всю конфигурацию; отдельного файла журнала нет.

## Управление эфиром

Обычный эфир запускается штатной кнопкой OBS. Сервер создаёт Session либо
присоединяет вход к уже работающей; плагин подхватывает её состояние.
Команды выходов в Dock не включают трансляцию OBS.

Пауза и возобновление управляют сервером, сохраняя передачу OBS. Завершение
эфира сначала запрашивает остановку OBS, включая переподключение, затем
завершает конкретную серверную Session. Интерфейс показывает результаты двух
частей отдельно: неподтверждённая остановка OBS не становится общим успехом.

Блок «Статистика выходов» показывает сохранённые назначения выбранного потока
даже до начала эфира. В каждой строке — название, состояние и битрейт;
переподключения, очередь и потери доступны в подсказке. Без наблюдений
показывается «Нет данных».

Меню «…» справа позволяет запустить выбранное назначение без предварительного
запуска OBS. Для этого нужна подготовленная совместимая заглушка: плагин создаёт
серверный сеанс только с этим назначением либо добавляет его в уже работающий.
Участие назначения в следующем эфире не меняется. В меню остаются запуск,
остановка, перезапуск и «Подробности». Последний пункт открывает настройки
показанного назначения, в том числе до запуска эфира.

Три иконки у заголовка — «Запустить все», «Остановить все» и «Перезапустить все».
Они работают только со списком показанных выходов выбранного потока, включая
строки за прокруткой. Запуск сохраняет уже работающие выходы; перезапуск
останавливает и заново запускает существующие, а также запускает остановленные.
Остановка выходов сохраняет основной поток OBS и серверный сеанс. Для полной
остановки используется отдельная команда «Завершить эфир».

Массовое действие фиксирует состав до подтверждения. Локальная ошибка
одного выхода позволяет продолжить остальные,
пока подтверждён тот же серверный сеанс и сохраняется связь. Потеря общей цели
останавливает оставшиеся команды. Неизвестный результат сохраняется отдельно;
явный повтор касается одной указанной команды и не возобновляет остаток пакета.
Перезапуск состоит из подтверждённой остановки и отдельного запуска; он прерывает соединение.
В строках выходов отображаются наблюдаемые состояние и битрейт. Развёрнутый
текстовый отчёт о командах в Dock не выводится. Числовые показатели OBS
показываются без подписей «С момента сброса» и «Текущий запуск»;
локальный сброс счётчиков сохраняет прежнее действие.

Внизу Dock показана версия с коротким хешем коммита сборки, например
`0.1.0+8d1a83f`. Сборка без доступных метаданных Git показывает `+unknown`.

После аварии или повторного открытия OBS плагин перечитывает сервер.
Продолжающийся эфир может передавать заглушку при остановленной OBS.
Старые команды и незавершённые пакеты автоматически не повторяются;
закрытие окна управления не останавливает эфир.

## Серверная конфигурация

Разделы «Потоки», «Выходы», «Группы кодирования» и «Профили» содержат списки
и карточки для создания, изменения и удаления. Просмотр карточки не меняет
рабочий Stream; его выбор остаётся в шапке Dock. Первый Stream можно создать
до рабочего выбора. Ключ публикации задаётся при создании и затем неизменяем.

Ключи и полный адрес назначения изначально замаскированы. Показ и копирование
работают независимо; копирование сохраняет точную строку текущего поля. Смена
карточки и повторное открытие окна возвращают маску. Неизменённые секреты
не отправляются при PATCH; явный пустой ключ назначения очищает его.
Адрес и ключ изменяются в этих же полях и сохраняются общей кнопкой
«Сохранить». Сервис трансляции выбирается по понятному названию.

В карточке потока выберите назначения следующего эфира. Новое назначение
сначала выключено; его нужно отдельно отметить в потоке. Сохранение состава
не меняет работающие выходы. При частичном отказе показан результат каждого
назначения, а несохранённый выбор остаётся в форме. Страница «Потоки» содержит
только редактирование потока и его назначений; сводка групп кодирования
и действия с заглушкой в ней отсутствуют.

Редактор профиля разделяет видео и звук и сохраняет полный профиль dev.8
с явным LIVE-аудиорежимом и настройками encoding без выбора версии.
Доступны поддержанные сочетания H.264/AV1/HEVC/VP9, SDR/HDR, CBR/VBR/CQP/CRF,
AAC LC и Opus/FLAC/MP3/AC-3. Списки зависят от выбранных настроек; несовместимое
исходное значение остаётся видимым, пока пользователь явно его не исправит.
QP и CRF сохраняются точно. Дополнительные параметры собираются отдельными
контролами; произвольная команда FFmpeg не вводится.
Неизвестный исходный профиль можно переименовать без пересборки его содержимого.
Изменения относятся к будущему запуску или новому прикреплению; текущий Output
использует прежний снимок. После изменения параметров может потребоваться
переподготовка заглушки на сервере.
В основном виде доступны девять параметров; подробности раскрываются
в «Расширенных настройках». Битрейты задаются в кбит/с, частота кадров —
одним параметром FPS. Три базовых пресета копируют полные настройки
существующих профилей владельца; они применяются только после явного выбора.
Значок справки у видеобитрейта показывает текущие основной и максимальный
битрейты. Для CBR они должны совпадать; максимум задаётся в расширенных
настройках. Подсказка не меняет значения автоматически.

Локальная проверка формы указывает недопустимый параметр. Отказ сервера
показывается в общем всплывающем окне и записывается в журнал OBS.
Подтверждённое сохранение выделяется зелёным. Введённые значения при ошибке
остаются в черновике; сообщение об ошибке не означает сохранение на сервере.

Конфликт ревизии требует сравнить исходную, свою и серверную версии и явно
подтвердить повторную запись. При потере ответа результат остаётся неизвестным:
сначала перечитайте состояние. Плагин не повторяет CRUD автоматически.
Несохранённый ввод живёт в памяти и переживает скрытие окна и переходы между
разделами, но не перезапуск OBS.

Страница «Выходы» содержит только редактирование сохранённых назначений.
Принадлежность потоку, группа, сервис, адрес и ключ применяются кнопкой
«Сохранить» для следующего запуска. Работающий эфир сохраняет прежние
параметры. Отдельных кнопок прикрепления и отсоединения, второго селектора
и блока заглушки здесь нет. Управление подготовкой и запуском заглушек
будет согласовано отдельно. «Подробности» в Dock открывает карточку
сохранённого назначения соответствующего выхода.

## Сборка

Нужны CMake 3.28+, Visual Studio Build Tools 2022 с MSVC v143 и Windows SDK
10.0.26100.0. Visual Studio IDE не требуется. Исходники используют C++20
и Qt 6 Core/Widgets/Network.

Выполните из корня репозитория в PowerShell:

```powershell
cmake --preset windows-x64
cmake --build --preset windows-x64
cmake --install build_x64 --config RelWithDebInfo
```

При конфигурации закреплённые зависимости OBS и Qt загружаются в `.deps/`
с проверкой SHA256. Их версии и источники заданы в [buildspec.json](buildspec.json).
Глобальная установка SDK не нужна. CMake устанавливает результат в
`build/install/` внутри проекта.

Конфигурация `RelWithDebInfo` включает символы отладки. Для сборки `Release`:

```powershell
cmake --build --preset windows-x64-release
cmake --install build_x64 --config Release
```

## Тестирование

Локальные тесты проверяют разбор API и SSE, состояние, настройки, асинхронную
сеть, квитанции и последовательности команд, остановку OBS через управляемый
двойник и жизненный цикл интерфейса. Также проверяются CRUD/ревизии/Unknown,
полный профиль и секретные поля, зависимые селекторы, настройки,
однократная доставка отказа в диалог и журнал согласно принятой политике.
Запуск без обращения к внешнему серверу:

```powershell
ctest --preset windows-x64-offline
```

Для проверки связи со своим сервером после сборки задайте его адрес:

```powershell
$env:GOST_TEST_BACKEND_URL = 'http://192.168.1.100:8080'
ctest --test-dir build_x64 -C RelWithDebInfo --output-on-failure
```

Серверный тест выполняет только GET к `health/live`, `health/ready`
и `system/capabilities` внутри `/api/v1/`. Полные тестовые presets
`windows-x64` и `windows-x64-release` используют адрес из
[CMakePresets.json](CMakePresets.json).

Тестовые конфигурации, временные файлы и журналы размещаются внутри проекта.
Для проверки с настоящим OBS используется отдельная portable-копия;
GUI-тесты в offscreen-режиме не заменяют проверку нативного интерфейса.
Для проверки профилей и окна отказа в настоящем OBS используется
[Test-Dev8ProfileNative.ps1](tests/integration/Test-Dev8ProfileNative.ps1):
после базового portable-прогона он работает с локальной HTTP-фикстурой в памяти,
при масштабе 100%, отдельно для `ru-RU` и `en-US`. Параметры запуска приведены
в [профиле проекта](CODEX_PROJECT.md). Рабочий сервер и эфир для этого не используются.
