# GOST Restreamer — плагин OBS

Нативный плагин OBS Studio для подключения к серверу
[GOST Restreamer](https://github.com/GregoryGost/gost-restreamer).
Компактный Dock показывает состояние подключения и выбранный поток,
а отдельное окно содержит управление и настройки.

Проект находится в разработке. Сейчас доступны подключение к серверу,
автоподключение и восстановление связи, выбор потока и сохранение настроек.
Выбор запоминается отдельно для каждого сервера и профиля OBS;
переименование профиля сохраняет его привязки. Интерфейс доступен на русском
и английском языках.

Команды управления эфиром, подробная статистика и редакторы серверной
конфигурации пока недоступны. Кодирование и отправка исходного медиапотока
выполняются штатными средствами OBS.

## Совместимость

- Windows 10/11 x64.
- OBS Studio 33.0.1.
- Отдельный сервер GOST Restreamer с доступным HTTP/HTTPS API.

Поддержка Linux и macOS пока не заявляется. Контракт серверного API
и границы совместимости описаны в [архитектуре проекта](gost-obs-plugin-architecture.md).

## Установка

Установщик пока не подготовлен. Плагин можно [собрать из исходников](#сборка).
После сборки и установки в staging каталог плагина имеет следующую структуру:

```text
build/install/gost-restreamer-obs-plugin/
  gost-restreamer-obs-plugin.dll
  gost-restreamer-obs-plugin.pdb    (символы отладки, если доступны)
  data/locale/ru-RU.ini
  data/locale/en-US.ini
```

Закройте OBS и скопируйте каталог `gost-restreamer-obs-plugin` целиком:

- для обычной установки OBS — в `%ProgramData%/obs-studio/plugins/`;
- для portable OBS — в `<OBS>/plugins/`.

Затем запустите OBS. DLL должна находиться непосредственно в каталоге плагина,
рядом с `data/`.

## Подключение

1. В Dock GOST Restreamer нажмите шестерёнку и откройте «Настройки».
2. Укажите корневой адрес API, например `http://192.168.1.100:8080`, без `/api/v1`.
3. Нажмите «Подключить» и дождитесь загрузки списка потоков.
4. Выберите нужный Stream. При необходимости включите автоподключение.

При смене сервера окно запрашивает подтверждение. Подключение и восстановление
связи сами по себе не запускают эфир. RTMP Server и Stream Key вводятся
в штатных настройках трансляции OBS.

При возвращении к серверу или профилю OBS восстанавливается сохранённый
для этой пары поток. Новые и дублированные профили получают собственные привязки.
Переименование через OBS сохраняет выбор, в том числе после перезапуска.
Ручное перемещение каталогов профилей при выключенном плагине автоматически
не распознаётся как переименование.

Настройки сохраняются в `settings.json` каталога конфигурации плагина;
в portable OBS он находится внутри `config/`. Серверные ключи, адреса
назначений и метрики в этот файл не записываются. Ошибка сохранения показывается
в интерфейсе; повреждённый или неизвестный формат файла не перезаписывается.

## Сборка

Нужны CMake 3.28+, Visual Studio Build Tools 2022 с MSVC v143 и Windows SDK
10.0.26100.0. Visual Studio IDE не требуется. Исходники используют C++20
и Qt 6 Core/Widgets/Network.

Выполните из корня репозитория в PowerShell:

```powershell
cmake --preset windows-x64
cmake --build --preset windows-x64
cmake --install build_x64 --config RelWithDebInfo
```

При конфигурации закреплённые зависимости OBS и Qt загружаются в `.deps/`
с проверкой SHA256. Их версии и источники заданы в [buildspec.json](buildspec.json).
Глобальная установка SDK не нужна. CMake устанавливает результат в
`build/install/` внутри проекта.

Конфигурация `RelWithDebInfo` включает символы отладки. Для сборки `Release`:

```powershell
cmake --build --preset windows-x64-release
cmake --install build_x64 --config Release
```

## Тестирование

Локальные тесты проверяют разбор API и SSE, состояние, настройки, асинхронную
сеть и жизненный цикл интерфейса. Запуск без обращения к внешнему серверу:

```powershell
ctest --preset windows-x64-offline
```

Для проверки связи со своим сервером после сборки задайте его адрес:

```powershell
$env:GOST_TEST_BACKEND_URL = 'http://192.168.1.100:8080'
ctest --test-dir build_x64 -C RelWithDebInfo --output-on-failure
```

Серверный тест выполняет только GET к `health/live`, `health/ready`
и `system/capabilities` внутри `/api/v1/`. Полные тестовые presets
`windows-x64` и `windows-x64-release` используют адрес из
[CMakePresets.json](CMakePresets.json).

Тестовые конфигурации, временные файлы и журналы размещаются внутри проекта.
Для проверки с настоящим OBS используется отдельная portable-копия;
GUI-тесты в offscreen-режиме не заменяют проверку нативного интерфейса.
